## 一、用户报「音频放进去了为什么不能播」

排查结论：**「把 mp3 丢进 `frontend/public/audio/`」只是第一道门**，实际要过三关，
少一关就是静音，而且**控制台不报任何错**（所以用户会觉得「文件明明在」）：

| 门 | 卡在哪 | 本次实际情况 |
| --- | --- | --- |
| ① 文件名 | `stores/audio.ts` 硬编码 `/audio/lobby.mp3` 等四个名字 | 用户放的是 `M500004Kf8Gs3zQ8p9.mp3`（音乐 App 下载名），对不上 |
| ② manifest 开关 | `setTrack()` 在 `availableTracks[track]===false` 时**直接 return，连 `new Audio()` 都不执行** | `manifest.json` 四个轨道全是 `false`（项目默认如此，为了避免请求不存在的文件） |
| ③ 重新构建 | `vite preview` 服务 `dist/`，`public/` 只在 `vite build` 时才被复制 | 用户只往 `public/` 放了文件，`dist/audio/` 里还是 9-17 的旧内容 |

处理：按用户选择（四个场景都用这一首）把文件复制成 `lobby/investigation/tension/result.mp3`，
manifest 四轨改 `true`，重新构建前端。

## 二、新建 `frontend/scripts/audio-bgm-check.mjs`（12 项，浏览器级）

零件对不代表**接线**对，所以补了这一层：manifest 开关 → 是否真的发 mp3 请求 → 能否解码
→ **首次手势后是否真的在播**。12/12 通过（readyState=4、duration=233s、currentTime 前进、无报错）。

**写这个脚本时我自己犯了两个错，都写进脚本注释了，别改回去：**

1. **断言「mp3 必须返回 200」→ 假失败。** 浏览器对媒体用 Range 请求，返回的是
   **`206 Partial Content`**。正确判据是「200 或 206」。
2. **用 `document.querySelector('audio')` 找元素 → 永远找不到。** store 用的是
   `new Audio(...)`，**该元素不挂到 DOM 上**。必须用 `addInitScript` 拦 `window.Audio` 构造器
   才能观察到实例。
3. 还有一个「断言与设计自相矛盾」：我断言「`play()` 不被拒绝」，但**手势前抛
   `NotAllowedError` 正是设计预期**（README 写了「这不是错误状态，而是『等一下就播』」）。
   改成只在**手势之后**统计拒绝才有意义。

- `result` —— `CaseDetailView.vue:561`

所以往 `tension.mp3` 放音乐**不会有任何效果**。已写进 README 提示；**未擅自补触发点**
（那是新增功能，该由用户决定放在哪个交互上）。

## 四、另外两点值得记住

- **BGM 默认音量是 0.25**（`stores/audio.ts:36`），比较轻 —— 「没声音」有时只是「太小声」。
- **`frontend/public/audio/*.mp3` 本来就在 `.gitignore` 里**（项目刻意不入库版权音频），
  所以音频文件不会被提交。**`manifest.json` 我也没提交**：它是被 git 跟踪的，
  若把 `true` 提交上去，别人克隆后只会得到一堆 404 —— 它本质是「本机装了哪些轨道」的本地配置。
  代价是这个文件会一直显示为 modified。
